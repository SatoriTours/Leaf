# Leaf 标准组件库设计方案：对齐 shadcn/ui

日期：2026-11-07  
状态：**用户已确认设计并授权继续 M0＋M1 实现；未授权提交或发布。**

## 1. 已确认的方向与目标

用户已选择：以 shadcn/ui 的视觉规范、组件分类和交互语义建立 Leaf 标准组件库，不再以自创松石风格作为新组件的设计基准。沿用丰富的组件目录，按可验收切片落地，而不是一次宣称全量支持。

产品定位：**shadcn/ui 设计体系的 Leaf 原生实现**，不是官方移植，不承诺 React API、DOM 或 CSS 兼容。

目标：
- 开箱即用的统一浅／深色组件，能够组合成完整桌面应用。
- 保留 Nim 声明式、单一托管 Runtime、稳定身份、状态驱动和 Win32 原生输入。
- 每个组件提供结构、状态、键盘、可访问性、示例和能力边界。
- 用真实 Windows 组件展示应用及设置／数据管理页面证明组合能力。

非目标：
- 引入 React、Tailwind 运行时、WebView、Radix JS 或恢复旧渲染桥接。
- 为视觉统一将全部控件改为 Canvas；从零重写输入法和文本编辑。
- 本期实现 Linux/macOS GUI，或借本方案宣称 Android 已达到相同组件覆盖。
- 首版完成全部 61 项、Excel 式表格、全部图表或上游网站／营销页面。
- 未经确认改变既有应用的默认主题，或删除松石和系统主题。

### 2.2 对齐与例外

| 维度 | 要求 |
| --- | --- |
| 视觉 | 对齐 Neutral 色板、组件结构、间距、尺寸、圆角、边框、焦点环与状态；不额外混入 Fluent 或松石视觉 |

系统高对比优先于品牌还原。动画和阴影若尚未实现，应记录差异，不能先换成无关效果再声称完全一致。

### 2.3 方案比较与选择

| 路径 | 取舍 | 决定 |
| --- | --- | --- |
| 现有原生底座＋统一主题＋组合组件 | 复用输入、状态、列表；补齐绘制、浮层和语义能力 | **采用，用户已选择此方向** |

## 4. 架构与代码边界

```text
应用／页面模板
       ↓
leaf/ui：标准组件及公开类型
       ↓
组件组合／状态契约／共享行为
       ↓
主题 token → typed 属性与能力校验
       ↓
现有 Runtime / Host 协议
       ↓
Win32 原生控件＋局部绘制＋浮层宿主
```

建议模块位置（尚未创建）：
- `src/leaf/ui.nim`：统一公开入口。
- `src/leaf/ui/tokens.nim`、`theme.nim`：平台无关设计变量及主题解析。
- `src/leaf/ui/<component>.nim`：标准组件组合；低层宿主能力仍位于现有后端目录。
- `src/leaf/ui/behaviors/`：选择、展开、焦点请求、菜单导航等纯逻辑；不能直接操作 HWND。
- Win32 浮层、测量、皮肤和辅助技术接入，沿现有后端模块边界扩展。
- `examples/ui_showcase/`：实际原生组件展示应用，随组件持续扩展。
- `docs/ui/`：用法、组件索引、状态／能力矩阵和原生差异。

这些是职责边界，不要求为了目录对称先建立空模块。简单组合不新增 NodeKind；只有真正缺失的宿主能力才扩展 typed 协议、能力表及各受影响后端。

## 5. 视觉变量与主题

### 5.1 Token

沿用上游语义：
- background/foreground、card/card-foreground、popover/popover-foreground。
- primary、secondary、muted、accent 及对应 foreground。
- destructive、border、input、ring。
- sidebar 系列、chart-1…5；预留其正式值不代表组件已支持。
- radius、字号／字重／行高、间距、尺寸、阴影、动效时长。

以 Neutral 原始 OKLCH 值为来源，明确转换到 sRGB 的算法、色域裁剪、舍入与透明度规则；不得将 OKLCH 明度直接当 RGB。带透明度的 border/input/ring 按实际表面合成，防止深色卡片上出现错误边色。对颜色转换及透明合成编写固定样例测试。

### 5.2 尺寸与绘制

- 标准映射：1 CSS px → 1 DIP，1 rem → 16 DIP；再由实际窗口 DPI 换算物理像素。
- 基线 Button：default 36 DIP、xs 24、sm 32、lg 40；icon 系列同对应方形尺寸。Input 默认高 36 DIP。来自已核读上游，不继承旧主题 96×32／40 DIP 的固定组合。
- 基础 radius 为 0.625rem（10 DIP），各组件按其 rounded token 推导，不全部使用 10 DIP。
- 桌面正文参照 14 DIP；系统字体和中文回退优先，测量与绘制必须用同一字体，允许长文本自动撑宽／换行，不以裁剪换取截图相似。
- 先补标准组件实际需要的布局／表面／边框／焦点能力；不为此承诺完整 CSS 引擎。
- 字体、画刷、位图、窗口资源沿现有所有权管理；重复更新和关闭不得泄漏。

### 5.3 兼容策略

- 新增可显式选择的 shadcn 浅／深主题，复用唯一主题解析路径；不让组件私下修改全局主题。
- 框架默认系统外观和既有松石枚举／调用先保留；枚举／协议新增不得重排既有数值或破坏序列化。
- 新 showcase 和新标准组件示例显式选择 shadcn；后续新生成应用在对应阶段切换，既有项目不自动迁移。
- 运行期切换在主题阶段实现：保留 HWND、编辑值、光标／选区和焦点；不以重建整个应用假装换肤。高对比切换也须实测。
- 旧 tag 等名称保留；新 Badge 在标准入口提供。旧 primary/danger 等语义不全局改写。

## 6. API、状态与行为

### 6.1 公开组件

建议通过模块限定调用标准组件，避免与现有构造器重名冲突。公开 API 采用 typed variant/size，不把任意 CSS 字符串当规范。

Button 对应 default/destructive/outline/secondary/ghost/link；与底层已有 primary/danger 的映射集中在适配层，按组件解释。新增 loading 是 Leaf 明确标注的组合能力，不伪称上游 Button 自带此属性；防止重复激活，保留可访问名称及稳定布局。

复合组件保留 Header/Content/Footer、Trigger/Content 等部件，但采用适合 Nim DSL 的组合方式，不机械模拟 React asChild。图标按钮必须有可访问名称；链接行为不得用普通点击按钮假冒。

### 6.2 状态契约

- value/checked/selected/open 等受控值由调用方 State 持有，事件只是提出变更。
- 可选局部状态复用 Leaf 组件状态与生命周期，受控／非受控模式创建后不可隐式切换。
- 组件 key、选项 key 与列表项身份稳定；退役事件不能更新新实例。
- Native EDIT 的输入、IME、选区、剪贴板、撤销继续由系统处理；Textarea 复用 multiline。
- 原生通知只入队，业务回调仍在现有普通 UI turn；不在 WndProc 内另跑 view 或修改业务状态。
- 新事件和实体遵循现有事务、预算与故障合同；不另建消息泵，不承诺 Win32 不具备的任意副作用回滚。

### 6.3 共用浮层与焦点基础

在 Select/Menu/Dialog 等组件之前建立共用宿主：
- 使用真正可跨父容器边界的原生弹出／owned 窗口，不把浮层画在会被裁剪的普通子窗口里。
- 管理 owner、层级、嵌套、工作区边缘避让、滚动后锚点、DPI 变化和卸载清理。
- Esc 优先关闭最上层；外部点击是否关闭按组件契约区分；不吞掉下一次业务输入。
- 模态限制背景交互及 Tab 范围，关闭后恢复触发器焦点；触发器消失则使用确定的合法目标。
- Menu/Select 支持方向键、Home/End、适用的字符定位及禁用项跳过；Select 提交与取消分离。
- Combobox 与 IME 输入中的方向键／Enter 需要区分，不抢走候选选择。
- 原生 UI Automation／MSAA 中建立适用的名称、角色、值、状态、标签／说明／错误关联；Canvas 级名称不算逐控件支持。

## 8. 可交付里程碑

### M0：基线与公共基础
产出 token、转换规则、typed API 映射、兼容测试和 showcase 骨架；先用 Button＋Input＋Card 验证真实绘制，不建立大量空壳。视觉对齐失败先修基础，不扩量铺组件。

### M1：基础表单切片（阶段 A）
完成 A 类组件和真实设置页：编辑、验证、错误保留草稿、保存／取消、禁用／执行中反馈。showcase 能查看各状态，切换浅／深主题。

### M2：选择与浮层切片（阶段 B）
先共用浮层＋Dialog＋Select，验收嵌套、焦点与关闭，再扩展其余组件。表单页可完成选择、确认危险操作和通知反馈。

### M3：应用与数据切片（阶段 C）
完成组件导航、列表／表格工具栏、搜索／筛选、选择、编辑、空态、错误恢复及 SQLite 持久化页面；复用原有模型／虚拟列表，不另造 ORM。数据表格先明确支持范围，禁止把大量实际子窗口一次性建满。

### M4：专项扩展（阶段 D）
按实际应用需求逐项推进，每个组件形成独立可验收切片，不为丰富目录强行实现用途尚未查清的组件。

执行上由一个实现负责人连续完成一个切片、自测和普通修复，再独立验收；不按文件或单次测试拆派。该文档不预估未经验证的人日，也不新增分支、空间或发布任务。

## 10. 验收标准与证据

### 10.1 分层检查

| 层次 | 必需证据 |
| --- | --- |
| 共享纯逻辑 | token 转换／合成、尺寸、受控状态、选择／展开、验证、事件与能力拒绝测试 |
| Windows 宿主 | 真实 HWND 属性／测量、绘制、输入与选区、浮层层级、焦点、增量更新、正常退出和资源归零 |
| 实际入口 | 编译并运行 showcase 及相应整页示例，真实键鼠路径；不能只调用 setter |
| 视觉 | 实际同版本 EXE 截图，独立查看浅／深色和主要状态，逐项比较固定上游基线；像素脚本仅辅助 |
| 可访问性 | 屏幕阅读器／平台辅助技术核适用角色、名称、状态及焦点；只有属性检查不算完整辅助技术验收 |
| 兼容回归 | 旧系统／松石主题、原生表单、列表、生成应用、协议和状态／生命周期受影响路径 |

具体维度：
- 100%／150%／200% DPI、窗口缩窄／放大、长中文与英文、中文 IME、键盘 Tab/Shift+Tab。
- 高对比、减少动态效果、运行期主题切换；浮层还需工作区边缘、多层打开、owner 消失、跨屏 DPI。
- 状态覆盖按组件适用性列出；不要求没有错误语义的装饰组件硬造错误态。
- 颜色、尺寸和布局可精确断言；字体栅格差异不做逐像素绝对等同比较，裁剪／遮挡／焦点不可见仍不接受。
- 动画如在该阶段支持，须动态证据；静态截图不证明动画和帧率。
- 反复创建／更新／开关浮层后 HWND/GDI 等资源稳定，正常关闭无残留；虚拟化保持有界，不预设未经测量的 FPS 宣传指标。

### 10.2 CI 与本地分工

复用现有 `.github/workflows/ci.yml` 的共享 `scripts/test.nim` 和 Windows `scripts/test_win32.nim` 入口，并按变更影响核对 database/model/windows-sdk-check 等既有工作流及触发条件；不擅自新增工作流。常规实现先运行受影响测试，最终提交交付按项目既定清单完成全量测试；Actions 已覆盖部分本地不重复。
