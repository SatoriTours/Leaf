**Goal:** 让 Leaf 的 Windows 主程序在 GPUI 创建窗口前启用正确 DPI 感知，并提供可复核的实际缩放诊断。

**Architecture:** CLI 构建时嵌入 PerMonitorV2 应用 manifest。直接 Nim 编译路径通过桌面入口检查/初始化 DPI；ready 请求携带 GPUI 测量数据，沿现有 JSONL 诊断通道输出。布局和字形继续交给 GPUI 处理一次设备缩放。

**Tech Stack:** Nim 2.2.6、Rust 1.92+、GPUI Kit 0.7.0、锁定的 gpui-pre 0.3.7、现有 Windows MinGW/Win32 API。

**Spec:** `docs/superpowers/specs/2026-10-06-windows-dpi-36dbf599-design.md`

### Task 1：桌面 DPI 初始化（P2、P5）

**Interfaces:** `windows_dpi.nim` 导出 `DpiApi`（`current: proc(): string` 和 `setPerMonitorV2: proc(): tuple[success: bool, errorCode: int]`）、`DpiResult`（`awareness, status: string`，`errorCode: int`）、`ensureDpi*(api: DpiApi): DpiResult`、`initializeWindowsDpi*(): DpiResult`。awareness 为 `per_monitor_v2` / `per_monitor` / `system` / `unaware` / `unknown` / `not_applicable`。status 为 `already_set` / `initialized` / `host_context` / `failed` / `not_applicable`。

- [ ] 写决策测试并运行确认新接口缺失导致失败：已 PMv2 不调用 setter；system/per_monitor 不调用 setter、返回 host_context；unaware 设置成功后重新查询确认为 PMv2；setter 返回 false/error=5 时重新查询，只有有效上下文已为 PMv2 才算 already_set；仍 unaware/unknown 返回 failed。unknown 不盲设。

### Task 3：可复核渲染诊断（P3、P4、P5）

依赖 Task 1。**Interfaces:** Rust `Bridge::ready(&self, rendering: serde_json::Value) -> Result<(Response, bool), String>`；JSON 请求 `{op:"ready", rendering:{scale_factor, logical_size:{width,height}, device_size_calculated:{width,height}, dpi_from_scale_calculated}}`。scale/逻辑尺寸来自当前 `Window`；计算尺寸和推导 DPI 字段明确命名。Nim ready 仍接受缺 rendering 的旧消息。新版 Nim 仅在成功 ready 响应加可选 `{capabilities:{rendering_diagnostics:true}}`；旧版 Rust 忽略未知响应字段，旧 Nim 忽略 ready 请求的可选 metadata。

`Bridge` 在 `bridge.rs` 增加私有 `request_value(&self, value: Value) -> Result<Value,String>` 复用原回调、生命周期和 snapshot 验证；现有 request 用它反序列化 Response，ready 用原 Value 读取能力并反序列化 Response，不改 model.rs 或 C ABI。ready 返回的 bool 只有字段严格等于 JSON true 且 Response.error 为空时为 true；缺字段/false/字符串/错误响应全部为 false。

新增 `Bridge::rendering(&self, rendering: serde_json::Value) -> Result<Response, String>`，只发送 `{op:"rendering",rendering:...}` 诊断请求，不执行 ready。`Desktop` 的能力标记初始为 false，只有首次成功 ready 明确协商支持后变为 true；首帧前 bounds 回调、旧宿主缺能力字段、ready失败时均禁止发送新 op。`Desktop::new` 使用锁定 GPUI `Context::observe_window_bounds(window, |desktop, window, cx| ...)` 订阅变化，在回调读取更新后的当前 Window.scale_factor/viewport_size；仅能力已协商且 scale/size 有变化时发送 rendering。保存 Subscription 到 Desktop 生命周期，记录上次取样，避免自激循环；ready 发出的样本作为初始值。不得重复 ready 或重写 watch receipt。诊断请求不修改业务状态；即使已协商后的诊断发生错误，也只记录诊断错误，不把错误送入 Desktop.accept 或污染宿主错误状态。

- [ ] 添加 Nim ready 测试：无元数据仍通过，带元数据记录 phase=`rendering`，成功 ready 才宣告 rendering_diagnostics 能力；原 ready/watch receipt 语义不变、首屏失败不发布 ready/能力。新增 rendering 请求只写诊断，不写/重写 watch receipt、不改变 snapshot 或调用事件，失败不污染 ready。Rust 在 `bridge.rs` 单元测试捕获 ready/rendering JSON，断言 ABI=1、1.5 / 逻辑宽度640→计算宽度960、能力严格判断。先运行确认新接口测试失败。
- [ ] 在 `desktop.rs` 内增加状态化旧宿主 callback fixture，保留当前旧 handler 的未知op持久写error、ready拒绝、status/list不清error、成功event清error语义。用实际 Desktop 订阅/ready握手路径触发首帧前、握手后、重复 bounds 变化，断言没有 rendering 未知op、错误保持空、ready仅一次、watch receipt不重写、后续status/list/event正常。新版配对测试能力true后1.5→1.25或viewport变化产生新数据、无变化去重。旧DLL→新Nim用旧格式ready请求验证无能力要求、仍正常就绪。对缺能力、false、非bool以及ready失败逐一验证诊断保持关闭；不能只测能力解析而不测实际发送门槛。
